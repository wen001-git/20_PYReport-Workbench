## 已确认目标与核心约束

1. 为新加坡银行监管报告风险管理人员提供由 Python 脚本生成的操作工作台。
2. 直接调用确认脚本，不重新实现计算规则；保存原版及版本差异，运行可追溯。
3. 用户步骤按人工依赖交接划分，脚本内的连续自动计算不拆细。
4. 先独立开发，再嵌入现有大平台；上传下载复用平台文件服务器。
5. 单个无暂停入口的脚本不能自动切片为多个可运行阶段；需要适配时先形成确认的新版本。
6. 首版样例使用虚构数据；原版保护、运行条件记录与结果基准验证分别处理，不能互相替代。
7. 支持前端和算法工程师分别维护；建议薄后端随工作台模块维护，无需为此单独建服务或增设专职岗位，但承担者需具备相应能力。

## 阶段 0：需求与架构评审（当前）

**交付**：需求说明书、总体流程/数据流/逻辑架构、页面与交互、执行与历史规则、集成契约、验收场景及本计划。

**技术基线**：原生 HTML/CSS/JavaScript + Python/Flask/Waitress + SQLite。公司截图记录的基础组合测试已通过，版本与证据边界见 [01 开发环境记录](01_DEVELOPMENT_ENVIRONMENT.md)；尚未验证本项目业务功能。

**待确认**：两模块中薄后端的归属方案、首版功能、代表性脚本形式与运行方式、逻辑架构及隔离方案；补全公司 Python 版本和完整依赖清单。关键结论明确后再开始应用编码。

**完成标准**：重要未决项有用户决定；先做什么、何时算完成、哪些限制需显示都可明确说明。

## 阶段 1：界面与配置验证（是否单独做原型待定）

**交付**：脚本与工作台配置、任务列表与详情、代码差异/历史视图、操作查询的页面与交互。采用虚构任务、文件和执行状态。

若用户选择直接做可运行版，可将界面验证并入阶段 2，不另建一套无法复用的原型。

**完成标准**：连续计算不被拆细，人工交接明确；缺输入、执行失败、替换文件、上游变化时，用户能看懂可执行动作。模拟状态明确标注。

## 阶段 2：最小可运行闭环

**建议范围，待确认**：一套受控 Python 样例、虚构数据、人工核实的配置、已确认版本执行、本地文件适配、任务状态、输出下载与基础历史。

**实施顺序**：

1. 按确认的维护边界建立项目骨架，确定元数据对象与本地文件契约；建议工作台应用包含页面和薄后端，算法模块独立维护，初期统一部署。
2. 实现原版保存、版本指纹、定义确认与发布，绑定真实可执行入口。
3. 实现输入和参数绑定、独立运行目录及选定执行保护；再开放运行。
4. 接通执行状态、产物保存、下载与尝试历史。
5. 验证整条路径，区分脚本失败、文件保存失败和未满足人工交接条件。

**完成标准**：虚构输入通过工作台调用确认脚本生成预期结果；执行版本、输入、参数、环境和输出可追溯。重复提交与失败不伪报成功。

**测试边界**：执行编排和保存路径使用相关最小测试；界面用必要的操作验证，不无差别全量测试。具体命令随实现记录。

## 阶段 3：版本、人工交接与重跑完善

**交付**：新旧及原版/执行文件差异、定义版本固定、人工替换与确认、重跑历史及下游失效、操作查询和运行恢复。

这些能力若被选为首版核心，应并入阶段 2，不以阶段编号推迟必需行为。

**完成标准**：旧任务不自动升级；替换有来源；重跑不覆盖历史；旧下游输出不被当成新输入对应的当前报告。

**测试边界**：集中验证版本篡改阻止、人工交接、重跑绑定、并发重复请求及失败恢复等直接风险。

## 阶段 4：真实脚本与业务基准验证

**前提**：用户提供可用脚本、依赖环境、代表性输入和原运行输出，并确认数据使用范围。

**交付**：兼容性评估、必要适配版本与差异、运行环境记录、基准比较和问题清单。按约定比较 Excel 内容、公式、格式及误差，不仅比较二进制文件。

**完成标准**：约定场景下的业务结果通过用户验收；未支持脚本能力和未覆盖条件被明确列出。测试通过不自动等同监管合规认证。

## 阶段 5：平台迁移与集成

**前提**：获得文件服务、身份权限、嵌入方式及 CRS Data History 接口资料，确认记录主源和部署约束。

**交付**：平台适配、身份和权限校验、数据及文件引用迁移、历史关联、集成测试与迁移说明。

**完成标准**：在目标环境完成授权上传/选择/读取/下载、真实脚本执行与历史查询；权限拒绝、接口失败、重试及运行恢复得到验证。旧运行记录与文件仍可追溯。
